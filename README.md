# 书织 · Bookloom Studio

本地优先的 TXT / EPUB 小说制作、精排、阅读与导出工作台。适配安卓与桌面浏览器，无需构建步骤或后端。独立实现，未使用参考应用的代码、图像或品牌资产。

## 运行

安装 Node.js 20+，在项目目录运行：

```sh
node server.cjs
```

打开 `http://localhost:8766`。也可以将 `dist/` 部署到支持 HTTPS 的静态托管平台。请使用 HTTP localhost 或 HTTPS，避免直接双击 HTML。PWA 离线缓存需要安全上下文。

## 当前已实现

- 批量导入 TXT、EPUB，导入前编码预览与手动切换；支持 UTF-8、UTF-16LE/BE、GB18030、Big5。
- 中文及英文章节识别、自定义正则、卷/章/节类型、章节增删、移动、合并、光标拆章、重分章。
- 清理空白、合并段内换行、移除重复标题及完全重复章节；推广段落逐条确认；全文字面/正则替换。
- OpenCC 简繁转换。
- 规整微圆角线稿气泡聊天、Twitter 风格帖子、信纸信件、社交动态、系统公告、作者的话、引用、列表组件；规则识别对话与作者说明。
- 8 个主题、横竖排、字号、行高、缩进、首字放大、标题配色与修饰线、3 种组件皮肤。
- 12 种封面配色 × 3 种版式，本地 Canvas 生成图片封面，上传封面与章节图片。
- TTF、OTF、WOFF、WOFF2 导入与 EPUB 字体嵌入。
- EPUB 3 导出，含 OPF、导航目录、NCX、封面、字体与章节图片；Kindle / 墨屏简化样式；批量 ZIP 导出。
- IndexedDB 本地书库、封面墙/列表、书名/作者/标签/文件夹搜索、阅读状态与评分。
- 内置阅读器、章节进度、书签与文字批注、前台阅读计时、半年热力图与阅读目标。
- 完整 JSON 书库备份与副本恢复、项目备份、编辑批量操作撤销、PWA 基础缓存。

## 尚未实现 / 兼容性边界

本项目是可用的首版，不等于两款参考软件的全部功能复刻：

- 尚无 AI 封面生成、iCloud/WebDAV/自动同步、亚马逊账户直传或邮件发送。可导出 EPUB 后自行用 Send to Kindle。
- 没有高级图片裁切、头像/通话/截图等组件子类型、人物资料库、素材分类库、完整多层目录组编辑。
- 封面为 36 个本地组合，不是参考应用的 39 套模板；没有复制参考应用素材。
- EPUB 原书 CSS、脚本、外链资源与交互不会完整保留。导入保留经过白名单清理的正文标记和支持的内嵌图片，转换使用应用自己的样式。
- 当前 EPUB 导出目录为顺序目录；卷章类型保留在页面结构，但未生成完整嵌套目录树。
- 自动编码选择是启发式，无法修复已经永久丢失的文字。错误识别应手动切换编码。
- 每文件导入上限 100 MB，EPUB 解压总量上限 200 MB；同步压缩可能短暂阻塞大文件界面。未完成超长小说性能验收。
- 不保证所有阅读器的 CSS 呈现一致。未完成 Kindle、Apple Books、微信读书真机兼容性测试，也尚未运行 EPUBCheck 全量规范校验。
- 阅读时长仅在阅读页且页面可见时每 10 秒计入；热力图为时长记录，不是封面日历。年度目标尚未按完成年份筛选。
- 本地存储与站点域名绑定，清理浏览器可能导致数据丢失；请定期备份。示例书内容为演示创作。

## 验证

```sh
node --check dist/app.js
node check.mjs
```

检查包含中文/英文分章、编码、组件 HTML 转义、EPUB ZIP 首项及未压缩 mimetype、目录/元数据/字体/图片资源、OpenCC。`check.mjs` 将生成 `test-output/roundtrip.epub` 及 XML 文件，可进一步交给 EPUBCheck。

## 目录

```text
dist/                 可直接托管的应用
  app.js              界面、导入、书库、阅读、备份
  core.mjs            文本解析、组件与 EPUB 生成
  vendor/             本地打包的第三方依赖及许可证
check.mjs             核心数据与导出验证
server.cjs            零依赖本地静态服务器
```

依赖为 fflate 0.8.2（MIT）与 OpenCC-JS 1.0.5（MIT），对应许可证保留在 `dist/vendor/`。应用代码采用 MIT。

## 新组件使用

选中文字后点击「聊天」「帖子」「信件」，或在「格式说明」中复制标记。聊天按人物固定左右位置，第二位出场者默认放右侧，也可使用 `[[chat|标题|我=姓名]]` 指定。`姓名 [09:41]：台词` 可显示时间；无人物前缀或以「旁白：」「动作：」「神态：」开头的行显示为居中灰色小字。头像为首字占位，不会自动获取真实头像。

帖子用 `昵称 @用户名 · 时间` 作为每帖开头，`---` 分隔帖子；`回复 3 · 转发 2 · 喜欢 12` 可填写静态数据。信件以 `[[letter|标题]]` 和 `[[/]]` 包围，可写「称呼：」「落款：」「日期：」，正文空行分段。三种新样式同时用于预览和 EPUB，墨屏模式降级为灰度。

组件默认不在书内显示「系统公告」「作者的话」「引用」「列表」「动态」「信件」「帖子」等类型标签，只保留样式和内容。使用 `[[system|标题文字]]` 等显式写入的自定义标题仍保留。

聊天现使用无背景、无填色的微圆角长方框与小尾巴，台词气泡上方显示人物姓名，旁白为灰色小字居中。姓名也用于左右分组，不显示头像、标题栏或时间；旧聊天标记继续兼容。
